📋 版本历史 — 提示词迭代记录
仅「出表情」提示词在 v1→v2 发生了变化。
「定基准（文字）」和「定基准（参考图）」两条提示词 v1 与 v2 完全相同，无需迭代。
v2 改动原因：测试中出现三联拼图（连续指令触发）和手部崩坏（手指数量错误）两类问题。
① 定基准 · 文字模式（v1 = v2，未变动）
[角色描述]，IP 吉祥物插画，表情包风格，正方形构图，角色主体居中，纯白背景，无文字水印，正面视角，标准站姿，中性表情
② 定基准 · 参考图模式（v1 = v2，未变动）
参考图中是一个 IP 角色形象，请生成同一角色的标准表情包图。严格保持角色的所有外观特征：脸型、颜色搭配、配饰细节、整体画风。构图：正方形，角色主体居中，纯白背景，无文字水印，正面视角。[额外风格要求：……（可选）]
③ 出表情 · 表情生成（v1 → v2 有改动）
🟠 V1 · 原始版本
严格保持参考图中角色的所有外观特征不变（脸型、颜色、配饰、画风风格必须与参考图完全一致）。只改变本次的表情和动作：[表情指令]。构图：正方形，角色主体居中，纯白背景，无文字水印。
🟣 V2 · 当前版本
只生成一张独立的单图，画面中只有一个角色、一个表情动作，禁止拼图/九宫格/分镜/多格漫画/边框分割。严格保持参考图中角色的所有外观特征不变（脸型、颜色、配饰、画风必须与参考图完全一致）。本次只改变表情和动作：[表情指令]。如有手部，手指数量正确、结构自然。构图：正方形，角色主体居中，纯白背景，无文字无水印，正面或四分之三侧面视角。
V2 新增两条约束：
1. 单图约束（首句）：「只生成一张独立的单图…禁止拼图/九宫格/分镜」 — 解决连续多个表情指令被模型画成拼图或只出第一张的问题（测试用例 P1-1）。
2. 手部约束：「如有手部，手指数量正确、结构自然」 — 解决比心/招手等动作手部崩坏（手指多余/缺失）的问题。
前端已将多指令拆分为多次独立 API 调用，prompt 层只处理单指令，约束更精确。
